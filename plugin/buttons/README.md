# buttons 插件：按键映射、连点、组合键与宏

这个插件改的是**主机看到的那一份按键状态**：手柄照原样上报，插件在交给主机之前
把其中的键位、扳机行程与摇杆轴重新排一遍。它不改手柄、不改协议、不改主机——
换一台设备接同一只手柄，这些映射就不存在了。

写在用户配置 `~/.config/ds5dummy/config.yaml` 的 `global.plugins.buttons:` 一节里，
那是所有手柄共用的默认；某只手柄要单独一套时写在
`controllers.<MAC>.plugins.buttons:` 下，只覆盖那一层里写了的键。两层之外没有第三层。
**改完要重启服务才生效**：
`sudo systemctl restart ds5dummy`（每一站拆掉重建，虚拟设备会消失
两秒左右）。

这一节整段不写，或者写了但一句都没读通，插件就完全不生效：一个字节都不改。

## 1. 键名

配置里左右两边用的都是同一族名字，snake_case、区分大小写、没有别名：

| 组 | 名字 |
|---|---|
| 十字键 | `dpad_up` `dpad_right` `dpad_down` `dpad_left` |
| 面部键 | `triangle` `circle` `cross` `square` |
| 肩键与摇杆键 | `l1` `r1` `l2` `r2` `create` `options` `l3` `r3` |
| 系统键 | `home` `pad` `mute` |
| Edge 才有 | `lfn` `rfn` `lpaddle` `rpaddle` |
| 摇杆方向 | `lstick_up` `lstick_right` `lstick_down` `lstick_left`，`rstick_*` 同理 |
| 触摸板 | `touch_left` `touch_right`（手指落在左/右半）、`touch_two`（两个触点同时存在）、`pad_left` `pad_right`（左/右半点击）、`swipe_up` `swipe_right` `swipe_down` `swipe_left`（四个方向划动） |

- **方向名只能出现在左边**（当源）。它们是从摇杆轴判出来的，不是手柄上报的位，
  主机那边没有"左摇杆上"这个位可以按。
- 触摸板那族同理是判出来的：`pad` 是手柄上报的那一个物理开关，`pad_left` 与
  `pad_right` 是"这个开关 + 手指落在哪一半"。
- 四个 Edge 键在普通 DualSense 上恒为未按下：给它们绑规则不报错，也永远不命中。
  插件不查手柄型号。
- 摇杆方向按阈值 48 个刻度（满偏 127）判定，带 10 个刻度的回迟滞，所以停在阈值
  上的摇杆不会一帧开一帧关。这个阈值目前是全局的，不能按条覆盖。
- 触摸板的半区在手指**落下去那一刻**定下，保持到那根手指离开：手指在面板上滑过
  中线不会让一次左半点击变成右半点击。
- 划动是**一次手势出一个**：够距离就出，之后一直维持到**所有**手指都离开面板，
  按住不动不会一下一下地出。想"划一下出几下"请配在 `macro` 那一节。

## 2. `remap`：映射

```yaml
global:
  plugins:
    buttons:
      remap:
        circle: cross          # 按 ○，主机看到 ✕
        square: triangle+keep  # 按 □，✕... 见下
        l2: r2                 # 左扳机的行程搬到右扳机
        mute: disable          # 抹掉 Mute
        lstick_up: dpad_up     # 上推左摇杆 = 十字键上
        pad_left: cross        # 左半点击 = ✕，右半点击照常
```

一条规则就是"一个源 → 一组目标"：

- 多个目标用 `+` 连起来（`square: l1+r1` = 按 □ 同时按下 L1 和 R1）。
- 默认**换掉**：源键不再出现在主机面前。想让它照常发出，值末尾加 `+keep`
  （`square: triangle+keep` = 按 □ 出 □ 也出 △）。
- 值是 `disable` 就是把这一位抹掉，没有任何目标补上来。
- 多个源映到同一个目标自然是 OR：任一按下即该目标按下，不需要专门写开关。
- **规则不会在两格里各走一步**：所有目标读的都是手柄这一帧的物理状态。
  `square: cross` 加 `cross: circle` 的结果是按 □ 出 ✕、按 ✕ 出 ○；□ 永远出不来 ○。
- 扳机的模拟量和它的按下位是同一个键的两半，映射时两半一起搬：`l2: r2` 之后
  右扳机的行程等于左扳机的实际深度（缓慢压就有缓慢的行程，不是一个开关）；
  不是扳机的键驱动扳机时按**全按**给出。反过来，`l2: disable` 会把左扳机的行程
  一起清零——游戏读扳机读的是轴值，只抹按下位等于什么都没抹掉。
- 十字键按四个方向位处理，不是"只有一个方向字段"：注入的方向在自己那一轴胜出，
  玩家另一轴的倾向保留，所以按着"上"再触发"右"得到的是"右上"；抹掉"右"而仍按着
  右上，主机看到"上"。同一轴的两个相反方向同时被注入时那一轴回到居中。
- 触摸板那族里，`touch_left` `touch_right` `touch_two` `pad_left` `pad_right` 可以当
  源；**四个划动方向不行**——一次划动没有"按住"的形态，映射它等于把一次手势拉成
  持续好几帧的按键。目标那一边这一族全都不行：主机看到的还是一只普通手柄，没有
  "左半"或"划了一下"这种位可以按。
- 换掉 `pad_left` 抹掉的是触摸板上那一次按下；换掉 `touch_left` 抹不掉任何手柄上报的
  键，因为它不是一个键，只是"手指落在左半"这件事。
- 绑在某一半上的规则只管那一半的那一次按下：写了 `pad_left` 之后，右半点击与落在
  中线附近（那 8% 的带里）的点击都照常发出。

## 3. `axis`：轴反向、居中与左右摇杆对调

```yaml
global:
  plugins:
    buttons:
      axis:
        swap_lstick_rstick: both      # 或 x / y：只换一根轴
        invert_rstick_x: true
        center_lstick: always
```

- `invert_<轴名>`：任意一根轴单独反向，用于"这个游戏的左右摇杆是反的"。轴名是
  `lstick_x` `lstick_y` `rstick_x` `rstick_y` `ltrigger` `rtrigger`。反向让静置点
  仍在静置：松开的摇杆主机读到的还是中心值，不会变成一根永远在缓慢输入的摇杆。
- `center_<摇杆名>`：`always` = 一直居中（摇杆静置时的抖动也不漏给游戏）；这一档
  不写就是缺省——只在某个方向被规则用作源并且正命中的那段时间里居中。摇杆名是
  `lstick` 或 `rstick`，整根一起。
- `swap_lstick_rstick`：`both` 整根对调，`x`/`y` 只换同方向的那一根轴。
- 值是 `false` 等于这句没写。
- 对调与反向都按**同一帧的原始值**一次算完，不会边改边读：`swap` 之后两边看到的
  是对方在这一帧的值，而不是自己刚写出去的那一份。
- 摇杆方向的判定始终读物理摇杆，不受这里的对调与反向影响。

## 4. `turbo`：连点

```yaml
global:
  plugins:
    buttons:
      turbo:
        cross: 20
```

按住那个键，主机看到它按每秒 20 次的节奏出现与消失；松手立即停止。范围 `1`..`60`。

- 一次开合至少要两帧才能表达，所以**实际达到的频率只会低于或等于配置值**，不会
  偏高。60 这种上限在正常帧率下就取不满。
- 能连点的只有手柄真的上报、而且真的是一个开关的那些键：扳机、触摸板、摇杆方向与
  触摸板判出来的那几种形态都不行（扳机的行程不是一个开关，触摸板只有一个物理开关，
  其余的压根没有位）。
- 连点与映射可以配在同一个键上：连点作用在物理按键上，映射作用在结果上，
  "连点 ○、显示成 ✕"是可达的组合。
- 连点期间那把键的按下位是真实存在的，所以"多久没人碰手柄就关机"不会被连点
  误判成静置。

## 5. `shortcut`：组合键与动作

```yaml
global:
  plugins:
    buttons:
      shortcut:
        1: "create+options: power_off"
        2: "home*2: power_off"
        3: "l3>750: power_off"
        4: "swipe_up+touch_left: power_off"
```

冒号左边是一组源（全部按下才算），右边是动作。本期动作只有 `power_off`：
让手柄自己关机。关机之后蓝牙随之断开，下次按 PS 键重新连上会被当作新的一站拉起。

时序写在左边的**末尾**，只描述整组键：

| 写法 | 含义 |
|---|---|
| `create+options` | 组合：两个键全部按下即命中，不看按了多久 |
| `l3~` | 单击：松手时按下时长短于 300 ms 才算 |
| `home*2` | 双击：两次按下的起点相隔短于 300 ms 才算 |
| `l3>750` | 长按：按下满 750 ms 即触发，不等松手 |

- `>` 后面的毫秒数范围是 50..10000；`~` 与 `*2` 的 300 ms 目前不能改。
- 一条规则只能有一个时序，写在组的中段（`l3~+r3`）或者写两个（`l3~*2`）都读不通。
- 命中之后的动作在下一个心跳周期才执行——识别与执行是分开的两步，输入路径上
  不会去做任何要等蓝牙的操作。
- **一次命中只发一次**：发送失败也不会下个周期重撞，想再要一次动作得把那些键
  重新按一遍。
- 命中过一次之后，这组键必须**全部松开**才允许再次触发。所以按住组合里的一个键
  反复敲另一个键，不会一下一下地出动作。
- 触摸板那族出现在组合里时，"按下"就是"这件事现在成立"：`touch_left` 是手指正落在
  左半，`swipe_up` 是这一轮手势里向上划出去了、手指还没全离开。上面那条"全部松开"
  的闸门因此对手势同样生效——一次上划只出一个动作，要第二个得先把手指全抬起来。

## 6. `macro`：宏

```yaml
global:
  plugins:
    buttons:
      macro:
        1: "circle~: l3+dpad_up"
        2: "lpaddle: r2"
        3: "swipe_right: cross"   # 向右划一下 = 出一声 ✕ 的脉冲
```

冒号左边的时序同上一节，右边是**一组同时按下**的键。命中之后这组键被按住约
80 ms 再自己松开——这个时长是为了跨过游戏采样输入的那几帧，手快也不会被漏掉。
右边只能是手柄真的上报的那些键与十字键方向，触摸板那族做不了目标（主机那边没有
对应的位）。

- 宏是**一次性**的，映射是**按住型**的：宏触发完就结束，那组键不会跟着你的手
  继续按着；要"按下 A 就等于按住 B"请用在 `remap` 那一节。
- 目标里含扳机时，那根扳机的行程按全按给出。
- 松开触发键之后脉冲照样走完；整段期间再按那组键不会续期，也不会重放。
- 80 ms 目前不能按条配置。目标里的先后顺序、一次触发里多段动作都不在这个插件里。

## 7. 哪一句读不通会发生什么

规则是**逐条**判的：某一条的键名写错、取值不合法，只有那一条不生效，日志里留一行
说清楚是哪一键、哪个值、为什么，其余照常工作；服务不会因此退出。

- 不认识的组名（例如还没实现的 `gesture`）与别的插件的键一律静默忽略。
- 整节没写 `buttons`，或者写的全部读不通 → 插件不生效，日志说一句 `not armed`。
- 生效时日志里那一行列出五组各装进了多少条，配了 `invert_rstick_x` 却在那行里
  数不到东西的情况不会出现。

## 8. 改完先自检：`buttons_check` 与 `buttons_web`

两个工具给出同一份判定：`buttons_check` 直接编进插件自己的语法层
（`tools/buttons_config.*`），页面服务器（`tools/buttons_web.py`）不重复实现语法，
只在需要判定时调用 `buttons_check --json`。两者都解析 `global.plugins.buttons`（带
`--mac` 时是叠过 `controllers.<MAC>` 之后的结果）那一节，把每一行的下场打出来——
变成规则、被整行忽略、还是这一条不生效（附上日志原文），最后给一行整节的武装摘要。
取值怎么判与运行期是同一段代码。两个工具都不装载插件、不连手柄、不碰正在运行的服务。

```bash
cmake -B build -DDS5DUMMY_BUILD_TOOLS=ON
cmake --build build --target buttons_check
```

### 8.1 `buttons_check`：命令行，只读

```bash
./build/buttons_check ~/.config/ds5dummy/config.yaml   # 源码树
buttons_check ~/.config/ds5dummy/config.yaml           # 装包之后在 /usr/bin
buttons_check ~/.config/ds5dummy/config.yaml --mac AA:BB:CC:DD:EE:FF
```

不带 `--mac` 时检查 `defaults` 层，也就是没有专属条目的手柄拿到的配置；带 `--mac`
时检查那只手柄叠加过 `global` 与 `controllers.<MAC>` 的结果。

退出码：`0` = 会生效且没有取值被拒；`1` = 有取值被拒，或整节没有可解析的规则
（插件不会生效）；`2` = 用法、文件或 YAML 错误。

一条什么也不改的合法配置（例如 `axis.invert_lstick_x: false`）与一个不认识的组名
（例如 `rempas:`）在输出里长得一样，都是"不产生规则"：插件对不认识的组名本来就
保持沉默，两者在语法层分不开。

### 8.2 `buttons_web`：本地页面，基础配置 + 按插件目录出现的面板

工具分两层：`tools/buttons_web.html` 是壳，`tools/panels/core.js` 与每个插件目录里的
`<插件名>.panel.js` 是面板。壳负责读文件、算哈希、保存与原子替换，并画顶部的两栏
（服务状态 + 配置层选择）、只读的当前状态与标签页；它启动时扫插件目录，为每个 `.so`
加载同目录、同名的面板脚本，并按当前层把每个插件的那一节取回来推给面板——面板不读
文件、不发请求。**配置层是所有面板共用的一份状态**：在顶部选全局还是某只手柄，
下面的基础配置、按键映射、自动关机一起换到那一层，面板自己不再画层选择器，也不关心
自己处在哪一层。插件那一部分由目录内容决定——随包的 `buttons.panel.js` 是按键映射
编辑器，`idle.panel.js` 是自动关机，没有面板脚本的插件退回通用键值编辑器。

基础配置覆盖根级 `enabled` / `bt_addr` / `log_level`、`global:` 与每只
`controllers.<MAC>` 的六项手柄设置（`bt_wait_s`、`audio`、`haptics_gain`、
`speaker_gain`、`usb_report_interval_ms`、`usb_model`）。留空 = 删掉这个键、回到上一层
或内置默认；手柄层里留空的项，下拉框与灰字会标出它从 `global` 继承到的值。只读的
"当前状态"在标签页之上：虚拟 UDC、插件目录、系统里认得的 DualSense 节点与
`/etc/ds5dummy/config.yaml` 的只读内容，不随标签或配置层变化；服务状态与配置文件
路径在它上面的设备条里。

```bash
ds5dummy-config                                    # 装包之后；默认编辑 ~/.config/ds5dummy/config.yaml
python3 tools/buttons_web.py                       # 源码树里运行同一个脚本
ds5dummy-config --config /path/to/config.yaml --port 18777 --no-open
ds5dummy-config --plugins-dir /path/to/plugins --no-open
```

两个包都装 `/usr/bin/ds5dummy-config`（入口）、`/usr/lib/ds5dummy/buttons_web.py`、
页面壳 `buttons_web.html` 与 `tools/panels/core.js`，以及保存前做判定的
`/usr/bin/buttons_check`；插件面板随各自的 `.so` 在插件目录里。`ds5dummy-config`
只把参数原样交给那个 Python 脚本；脚本按自身位置找页面壳与 core 面板，所以从源码树
与安装目录运行的是同一份代码。

按键映射那一节沿用上游 DS5Dongle-Studio 配置门户的形状：标签页
（概览/映射/连点/组合键/宏/轴/其他）、搜索框与卡片列表，取值从下拉框与复选框中选，
不需要手写 YAML。键表、区间与时序档位随这一节一起由服务端下发（`catalog`），与
`plugin/buttons/ids.cpp` 的 token 表同源。

页面固定在一个地址（缺省 `http://127.0.0.1:8777/`，`--port` 可换），没有令牌，
`--no-open` 之外的场合会直接调 `xdg-open` 打开它。按键映射只改插件的那一节，缩进相对
`buttons`。顶部第二栏是配置层：下拉框列 `global` 与每只手柄——包括连着但文件里还没写
的手柄；「添加手柄」里可以选一只连着的，也可以手写任意 MAC。两层之下都是
`plugins.buttons`，"所有手柄一套"写进 `global`，"这只手柄单独一套"写进对应的
`controllers.<MAC>`；新加的手柄在保存时补出 `controllers.<MAC>:` 这一行。保存到哪一层
就只替换文件里哪一段，其余内容逐字节不动（注释、引号、键序都保留）。改完点
"保存"只是写回文件：**让它生效仍要** `sudo systemctl restart ds5dummy`（页面顶部会把
这条命令列出来），和手改文件是同一条路。页面壳是唯一读文件、取每层插件节的地方，
面板只消费推给它的那一节——节里已经去掉层标识与路径前缀，面板不自己发请求。
用户配置文件还不存在时页面照常打开并标出
"还不存在"，第一次保存会自动创建它所在的目录与文件。

面板脚本与 `.so` 同目录、同名（`buttons.so` ↔ `buttons.panel.js`），所以两个宿主插件
目录里的插件都带得上界面；`--plugins-dir` 可以只扫指定目录（可重复），测试用得上。
面板脚本只是一段静态 JS，装载点只发登记过的那几个文件。

页面服务器需要 PyYAML，并需要一个 `buttons_check` 可执行文件做权威判定：缺省在
`build/`、`build-tools/` 与 `PATH` 里找，也可以用 `--check` 显式指定。找不到时页面
照常打开、可以浏览，但保存会被拒绝——它不写没校验过的配置。

几条边界：

- 只监听 `127.0.0.1`，地址固定，不发放令牌；每个请求仍要过 `Host` 与 `Origin`
  检查，别的网页发起的跨站请求会被拒。
- 只能编辑块状映射。写成行内形态（`buttons: {…}`）的那一节页面会标成不可编辑，
  请先在文件里展开成缩进的键值行。
- 层下拉框列出 `global`、文件 `controllers:` 下已有的每只手柄，以及已连接但还没写进
  文件的手柄（标成"未配置"）。选一只还不带 `plugins.buttons` 的手柄保存时，页面会在
  它的 `controllers.<MAC>` 下补出这条链；文件里没有、也没连着的手柄用「添加手柄」
  手写 MAC 加进来，同样在保存时补出条目。
- 空着一整层保存 = 删掉那一层的 `buttons:` 键（祖先的 `plugins:` 可能留下一个空值，
  宿主把它当作"本层不覆盖"）。文件在页面打开之后被别处改过时，保存会失败并提示先
  "从磁盘重读"，不会覆盖别人的修改。
- 取值不合法也能保存：页面把每一行读不通的地方标出来，但写回是本分，判定是插件
  `init` 的事——与手改文件时的行为一致。基础配置的标量值则由宿主解析器整份复查，
  写不进去的取值不会落盘。
- 按键面板校验的是**这一层**交上去的文本；`controllers.<MAC>` 那一层的手柄实际拿到
  的是 `global.plugins.buttons` 再叠上本层写过的键。要看合并后的结果用
  `buttons_check --mac`。

---

## 9. 这个插件不做的事

- 键盘按键、鼠标动作、多媒体键：虚拟手柄是单接口游戏手柄，能发出的只有它自己
  上报的那 23 个键位和六根轴。
- 摇杆死区与响应曲线：这一节做的是"换一根轴"，不是"改变一根轴的形状"。
- 六轴手势（拿手柄当鼠标）：还没有实现。触摸板的半区点击与划动已经做了，但判据是
  全局的：中线两侧那 8% 算"任意半区"、划动至少走出面板宽度的 12%（纵向按面板的
  实际形状折算过），这两个数都不能按条覆盖。
- 组合键之间的遮蔽检出（`r3` 与 `r3+dpad_up` 同时存在时谁先命中）：没有做仲裁，
  两条规则各自独立判定，所以真撞上时两条都会触发。
