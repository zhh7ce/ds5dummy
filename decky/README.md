# DS5Dummy（Decky Loader 插件）

让 Steam Deck 上通过蓝牙连着的 DualSense（含 DualSense Edge）以**有线手柄**的身份出现
在主机上：手柄手感、陀螺仪、触摸板、灯条、震动、扬声器与麦克风都照常，但游戏看到的是
一台 USB 设备。技术细节在仓库根目录的 `AGENTS.md`；这里只讲怎么装、怎么用、出问题看
哪里。

## 安装

1. 先装 [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader)。
2. 从本项目的应用 release（`v*` 标签）下载 `ds5dummy_decky.zip`。
3. Decky → 设置 → 开发者 → 从 ZIP 安装插件，选那个文件。
4. 回到 Decky 的插件列表，打开 **DS5Dummy**。

这个插件**不需要**先在系统里装任何 ds5dummy 的包，也不需要在 Deck 上编译：转发程序和
它的插件都随 ZIP 带在插件目录里。反过来，如果系统里已经装了本项目的 Arch 包
（`ds5dummy_hidraw`、`ds5dummy_l2cap` 或预编译的 `ds5dummy_bin`），两边会争同一批内核
模块与虚拟设备，启用时会被拒绝并提示先停掉 `ds5dummy.service`。

## 首次启用

拨开主开关，面板会依次显示：取模块 → 准备模块 → 启动程序。第一次启用要下载一份
约 1 MB 的内核模块（按当前内核 `uname -r` 精确匹配），之后就一直用缓存。

**先把蓝牙手柄连上再启用不是必须的**：没有手柄时服务照样就绪，手柄出现后自动接管。

启用之后可以关掉面板、回到游戏；开关状态会保存，重启 Deck、注销、Decky 重载之后仍
保持开启，并在开机时自动恢复接管。

## 插件在自己的目录里带了什么

| 路径 | 内容 |
|---|---|
| `bin/ds5dummyd` | 转发程序本体（预编译，装不了工具链的机器也能用） |
| `lib/` | 它需要的共享库（yaml-cpp） |
| `plugins/` | 程序插件：`idle.so`（闲置自动关机）、`buttons.so`（按键改写） |
| `share/doc/ds5dummy/` | 随包文档，含 `buttons.md`（按键插件的配置语法） |

**不要改插件目录里的东西**：插件更新会整目录替换。用户可写的位置在下面。

## 缓存、设置与日志

| 位置 | 内容 |
|---|---|
| `~/homebrew/data/ds5dummy/kmod/<内核>/<内核>.ko` | 已下载的内核模块，按内核分目录 |
| `~/homebrew/data/ds5dummy/logs/daemon.log` | 转发程序的 stdout/stderr，每次启动覆盖 |
| `~/homebrew/data/ds5dummy/daemon.pid` | 转发进程的 pid，插件后端重启后靠它认领已在跑的进程 |
| `~/homebrew/settings/ds5dummy/settings.json` | 开关与虚拟 UDC 数量 |
| `/etc/modprobe.d/ds5dummy-decky.conf` | 接管期间阻止 in-tree 驱动自动加载的黑名单 |

除那份黑名单外，插件不写任何系统目录；黑名单在停用与卸载时删除。

面板上的「清理内核缓存」只删当前内核以外的缓存条目；「查看日志」把 `daemon.log` 的
尾部与本插件自己的事件日志一起显示，可以一键复制。

## 系统更新之后

SteamOS 的系统更新会换内核，也会把 `/usr` 整个替换掉——所以这个插件不往 `/usr` 里装
任何东西：模块在数据目录里，程序在插件目录里。

换内核后第一次启用时：

- **有新内核的模块**：自动取回并接管，什么都不用做。
- **还没有**：面板显示「当前内核 `<uname -r>` 没有对应的驱动模块，暂时不可用」。这是
  正常的等待状态，模块发布之后点一次「重新检查」即可。

想确认当前内核：在 Konsole 里 `uname -r`，与面板上「内核」一行的值逐字相同。

## 三种「不可用」的区别

面板的「最近一次错误」会明确写出是哪一种，处理方式不同：

| 情况 | 含义 | 怎么办 |
|---|---|---|
| 没有对应模块（尚未发布） | 云端还没有这个内核的模块 | 等发布后点「重新检查」 |
| 取不到模块（网络不通） | 连不上 GitHub | 检查网络/DNS/VPN 后重试 |
| 校验失败，已丢弃 | 下载到的文件与当前内核不匹配 | 点「重新下载当前内核模块」 |

另外两种需要动手的状态：

- **系统里 `ds5dummy.service` 正在运行**：先 `sudo systemctl disable --now ds5dummy`。
- **已安装内核驱动包（DKMS）**：先 `sudo pacman -R hid-playstation-ds5dummy-dkms`。
  两个接管方不能同时在场。

## 面板上的按钮

| 按钮 | 作用 |
|---|---|
| 主开关 | 启用 / 停用。进行中会显示当前阶段，并可以取消（取消会回滚到操作前） |
| 重新检查 | 重新走一遍远端查询，缓存命中也强制查 |
| 重新下载当前内核模块 | 覆盖缓存条目并重新校验；运行中不可用，先停用 |
| 重启程序 | 只重启转发程序，不碰内核模块；改了 `~/.config/ds5dummy/config.yaml` 后用 |
| 清理内核缓存 | 删掉当前内核以外的模块缓存 |
| 查看日志 | 程序日志尾部 + 插件事件日志，可复制 |

## 卸载

Decky 的插件菜单里卸载即可。卸载前会执行一次停用：停掉转发程序、卸载定制模块、删除
黑名单、恢复 in-tree 驱动，之后才删文件。设置目录在卸载时一并删除；模块缓存与日志在
数据目录里，随 Decky 删除插件数据时清理。

## 已知限制

- 从休眠恢复后插件不主动检查：如果手柄没回来，关掉再打开主开关一次。
- 插件只在 SteamOS 未开启内核模块签名强制（`MODULE_SIG_FORCE` / lockdown）时可用；
  官方镜像默认没有开启。
- 内核模块只有 GitHub 一个下载地址，没有镜像。
- 多只手柄受 `dummy_hcd` 的 `num` 限制（缺省 3），见系统配置里的模块参数。
